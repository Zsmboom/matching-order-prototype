# 撮合业务模式 · 订单与发票管理原型

PRD 配套的可交互原型，单文件、零依赖，双击 `index.html` 即可在浏览器打开。

在线预览：https://zsmboom.github.io/matching-order-prototype/

包含 18 个页面，菜单按**三级结构**组织：平台端 → 业务模块 → 菜单。

**运营平台 · 订单管理**　撮合订单管理 / 总分订单与核销 / 订单退款申请与审核 / 额度扣减流水

**运营平台 · 财务管理**　资金交易流水明细 / 订单支付凭证管理 / 服务费订单

**运营平台 · 发票管理**　开票申请记录 / 能源发票 / 服务费发票

**客户端**　我的加油订单 / 我的退款申请 / 我的余额与额度 / 我的支付流水 / 我的开票申请

**油站端 · 财务管理**　油站账户管理 / 油站资金流水 / 服务费账户管理

油站端的订单类页面（接单、核销、扫码确认）本次不在交付范围。

每页底部「规则说明与设计口径」可展开，是给研发和测试看的逻辑说明（前置条件、操作可用性、提交后的处理、流程图）。

## 近期口径变更

- 订单列表字段：客户企业 → **总公司**，归属分公司 → **分公司**，总订单金额 → **加油金额**，去掉**对账状态**列
- **服务费拆为独立菜单**「服务费明细」：记录支付方（油站 / 客户），并有独立的支付状态与开票状态。订单页的支付状态与开票状态从此**只针对油款**
- 客户端是否展示服务费，取决于该笔订单的**支付方**：油站承担不展示、客户承担必须展示
- 服务费明细补齐**详情页**（计算过程、支付方与收款方、支付进度、开票信息）
- **订单补录**精简：去掉补录类型、油卡类型、运单号、总订单号、补录人；枪价改称单价；油款金额改为可手工修改（与自动计算值的差异会提示并记入日志）
- 删除全部**接口请求与返回留痕**（请求/返回 JSON、报文快照、接口路径），业务字段全部保留
- **总分订单**子单行只记该运单的额度扣减（占用前可用 / 本次扣减 / 剩余可用），不再摊服务费
- **订单退款**改版：发起方只有油站和运营平台，取消两道审批，「审核」退化为一次确认操作；退款状态为 待审核 / 审核中 / 已退款；补全退款详情页
- 新增**油站端 · 财务管理**三个页面：油站账户管理（余额 / 提现 / 提现配置 / 账户启停 / 账户明细抽屉）、油站资金流水、服务费账户管理
- 页面内已标出三处**待确认**：油站端登录的数据可见范围、账户启停的权限归属、服务费账户管理展示的主体
- 菜单改为**三级结构**：一级平台端（运营平台 / 油站端 / 客户端）→ 二级业务模块（订单管理 / 财务管理 / 发票管理）→ 三级菜单；权限边界即菜单树第一层
- 新增全站**二次确认弹窗**体系：动钱、改数据、不可逆的操作统一先弹确认，含后果说明、关键金额、核对信息与必填理由
- 订单页顶部统计只留**合计订单数量**与**合计金额**，且跟随筛选联动
- 订单详情重新分组为**交易详情 / 商品信息 / 客户信息 / 支付信息 / 发票信息**，支付与发票两段把油款和服务费并列展示
- 补录的**油机小票号与凭证影像改为非必填**，必填只剩补录原因；风控从卡入口改为事后可查
- **服务费明细 → 服务费订单**，新增申请开票（单笔 / 批量）与发票下载
- **发票明细 → 能源发票**；能源发票与服务费发票均新增**批量下载**（ZIP 打包 + 随包清单，排除冲红与作废）

## 发布成网页

把整个目录推到仓库，然后在仓库设置里开启 Pages 服务，指向该分支根目录。

注意：直接访问 raw 文件地址（raw.githubusercontent.com 等）打不开页面，只会显示源码——raw 服务返回的是纯文本类型。必须走 Pages 服务。

`.nojekyll` 是给 GitHub Pages 用的，避免它拿 Jekyll 处理静态文件。
