# 撮合业务模式 · 订单与发票管理原型

PRD 配套的可交互原型，单文件、零依赖，双击 `index.html` 即可在浏览器打开。

在线预览：https://zsmboom.github.io/matching-order-prototype/

包含 15 个页面：

**订单中心 · 撮合**　撮合订单管理 / 总分订单与核销 / 额度扣减流水 / 资金交易流水明细 / 订单退款申请与审核 / 订单支付凭证管理 / 服务费明细

**发票管理 · 撮合**　开票申请记录 / 发票明细 / 服务费发票

**客户企业端 · 撮合**　我的加油订单 / 我的余额与额度 / 我的支付流水 / 开票申请 / 退款申请

每页底部「规则说明与设计口径」可展开，是给研发和测试看的逻辑说明（前置条件、操作可用性、提交后的处理、流程图）。

## 近期口径变更

- 订单列表字段：客户企业 → **总公司**，归属分公司 → **分公司**，总订单金额 → **加油金额**，去掉**对账状态**列
- **服务费拆为独立菜单**「服务费明细」：记录支付方（油站 / 客户），并有独立的支付状态与开票状态。订单页的支付状态与开票状态从此**只针对油款**
- 客户端是否展示服务费，取决于该笔订单的**支付方**：油站承担不展示、客户承担必须展示

## 发布成网页

把整个目录推到仓库，然后在仓库设置里开启 Pages 服务，指向该分支根目录。

注意：直接访问 raw 文件地址（raw.githubusercontent.com 等）打不开页面，只会显示源码——raw 服务返回的是纯文本类型。必须走 Pages 服务。

`.nojekyll` 是给 GitHub Pages 用的，避免它拿 Jekyll 处理静态文件。
