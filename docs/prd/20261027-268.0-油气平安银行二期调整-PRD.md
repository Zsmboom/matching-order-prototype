# **需求背景&目标**

网货用油业务中，货主支付运费后按油气分油规则将部分运费转为司机油气额度，司机在油气额度内加油。匹配到结算后分油的运单，油气额度在运单结算完成后才实际分油，司机端若在此前展示预估油气额度，司机可能按尚未分油的额度加油，产生资损风险；货主运费支付渠道为电子钱包光大或平安时，运费以一笔付方式一次性付清（油气部分含在运费中），真实分油在货主实际支付成功后才发生。本需求为油气平安银行二期调整，统一司机端运单的预估油气额度展示条件，并明确电子钱包光大/平安渠道的分油触发时机。

**目标：**

1. 司机端运单的预估油气额度展示条件收敛：匹配到的分油方式=结算后分油的运单，运单列表、运单详情不展示预估油气额度；展示与支付渠道无关。
2. 明确电子钱包光大、平安渠道的分油触发时机：货主一笔付支付成功后按油气分油规则分油，实际分油额度在实付后才产生。
3. 明确中途修改支付渠道的判定口径：司机端展示与支付渠道无关、不随修改变化；实际分油按实付支付渠道判定。

# 需求概述

司机端运单列表、运单详情展示预估油气额度，司机据此在油气额度内加油。本需求调整三处口径：

1. **展示条件**：运单匹配到的分油方式=结算后分油的，司机端运单列表、运单详情不展示预估油气额度；分油方式=发货分油的运单，司机装货后照常展示。展示与支付渠道无关。
2. **分油触发**：网货运费支付渠道=电子钱包光大或平安时，货主一笔付支付成功后按油气分油规则分油，实际分油额度在实付后才产生。
3. **渠道修改判定**：中途修改支付渠道的，司机端展示不随修改变化；实际分油按货主实付时的支付渠道判定。

## 需求范围

本需求涉及司机端运单列表、运单详情的预估油气额度展示逻辑，以及电子钱包光大/平安渠道下货主一笔付成功后的分油触发逻辑。明确不做：货单列表、货单详情的展示调整（货单不在本需求范围）；网货后台油气规则配置调整；货主端支付页面调整。

## 产品流程

**流程说明**：

1. **货主发货**：系统为运单匹配分油方式（发货分油/结算后分油）。
2. **司机端展示判定**：分油方式=结算后分油的运单，运单列表与运单详情不展示预估油气额度（整字段隐藏）；分油方式=发货分油的运单，司机装货后展示预估油气额度。展示与支付渠道无关。
3. **中途修改支付渠道**：司机端展示不受影响。
4. **货主支付**：支付渠道=电子钱包光大/平安的，货主一笔付支付成功后按油气分油规则执行分油（真实分油额度在实付后才产生）；实付为其他支付渠道的，沿用既有分油逻辑。
5. **分油完成**：司机油气额度按分油结果入账，实际额度以司机油气额度账户为准。

## **功能说明**

### 运单（司机端）

司机端运单列表、运单详情的预估油气额度展示口径；本节为展示判定说明，运单页面的其他既有内容不在本需求范围。

1. **预估油气额度·展示条件**：分油方式=发货分油的运单，司机装货后展示预估油气额度；金额按油气分油规则预估计算。
2. **预估油气额度·不展示条件**：分油方式=结算后分油的运单，运单列表与运单详情均不展示（整字段隐藏，不显示占位符）；展示与支付渠道无关。
3. **展示判定时点**：按运单匹配到的分油方式判定；货主中途修改支付渠道，司机端展示不变化。
4. **分油完成后**：司机油气额度按分油结果入账，实际额度以司机油气额度账户为准；运单上的预估油气额度字段本身不因分油完成变化。

**枚举值与口径（预估油气额度展示状态）**

| 字段/状态 | 取值 | 什么情况下出现 | 由谁/如何处理 | 后续流转与下一节点展示 |
|-|-|-|-|-|
| 预估油气额度·展示 | 展示 | 分油方式=发货分油（与支付渠道无关） | 系统按运单匹配的分油方式自动判定 | 司机装货后，运单列表与详情展示预估油气额度（按油气分油规则预估）；货主支付后按实付渠道分油 |
| 预估油气额度·展示 | 不展示 | 分油方式=结算后分油 | 系统按运单匹配的分油方式自动判定 | 运单列表与详情整字段隐藏；分油时机按实付支付渠道与油气分油规则执行 |

### 分油触发（货主一笔付）

1. **触发条件**：货主运费支付渠道=电子钱包光大或平安，货主以一笔付方式一次性付清运费（油气部分含在运费中）。
2. **触发时机**：一笔付支付成功后，按油气分油规则执行分油，实际分油额度在实付后才产生；支付失败或未支付不分油。
3. **实付渠道判定**：分油以货主实际支付时的支付渠道判定；实付为其他支付渠道的，沿用既有分油逻辑。
4. **分油结果**：司机油气额度按分油规则计算入账。

### 支付渠道修改判定

1. **展示判定**：预估油气额度的展示只取决于运单匹配到的分油方式，与支付渠道无关；中途修改支付渠道不影响司机端展示。
2. **分油判定**：实际是否分油、何时分油以货主实付时的支付渠道为准。

**场景矩阵（运单分油方式 × 实付支付渠道）**

| 运单分油方式 | 实付支付渠道 | 司机端展示 | 实际分油 |
|-|-|-|-|
| 结算后分油 | 电子钱包光大/平安 | 不展示预估油气额度 | 一笔付支付成功后按分油规则分油 |
| 结算后分油 | 其他支付渠道 | 不展示预估油气额度 | 沿用既有分油逻辑（结算完成后分油） |
| 发货分油 | 电子钱包光大/平安 | 装货后展示预估油气额度 | 一笔付支付成功后按分油规则分油 |
| 发货分油 | 其他支付渠道 | 装货后展示预估油气额度 | 沿用既有分油逻辑 |

# 测试重点

1. **结算后分油判定**：分油方式=结算后分油的运单，司机端运单列表与运单详情均不展示预估油气额度，与支付渠道无关；分油方式=发货分油的运单装货后正常展示。
2. **一笔付分油**：支付渠道=电子钱包光大/平安时，货主一笔付支付成功后按分油规则分油，分油金额与司机油气额度入账正确；支付失败或未支付不分油。
3. **渠道修改判定**：中途修改支付渠道的运单，司机端展示不变；实际分油按实付支付渠道执行。
4. **判定时点分离回归**：中途修改支付渠道后按实付渠道分油——实付为电子钱包光大/平安的按分油规则分油、实付为其他渠道的沿用既有逻辑，全程司机端展示不变。
