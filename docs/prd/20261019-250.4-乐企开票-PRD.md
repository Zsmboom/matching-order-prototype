# PRD 正文（对应公司模板章节，逐块替换用）

## 3 需求背景&目标

**背景**：《国家税务总局关于在成品油零售领域全面推广"交易即开票"有关事项的公告》（2026 年第 11 号）要求 2026-11-01 起全国成品油零售加油站全面推行"交易即开票"，既要保证笔笔开票及时性，又不能影响业务。平台能源订单当前依赖线下开票流程，无法满足按订单笔笔实时开票的要求。

**目标**：凡**柴油 ＋ 易宝支付 ＋ 网点一级渠道=自营**三个条件同时满足的能源订单（撮合易宝模式＋自营模式），支付成功后系统实时调用乐企自动开票，交易与开票解耦。乐企开的是**油站开出的票**：销方=油站公司，购方按业务线取（自营=平台内部主体、撮合=客户公司）；自营中**平台开给客户的销项票仍走线下开票后上传**（现网客户开票已有能力，本期不改）。订单列表呈现开票渠道、开票状态、失败原因与发票附件，支持手动开票、手动红冲、批量下载；退款审核通过后按退款类型分别处理（整体退款/油站退款先红冲油站开出的蓝票再退款，客户退款不红冲），退款过程落在客户侧「司机支付状态」、油站侧结果落在「油站扣款状态」「油站扣款状态」；网点公司管理提供「线上开票失败 n 笔自动下线」熔断配置；开票中心落地「订单发票管理」（现网已预留同名菜单）沉淀撮合＋自营的乐企发票全量历史。

## 4 名词解释

| 名词 | 释义 |
|---|---|
| 乐企 | 税务部门面向企业的发票数字化开放平台，本需求使用其发票开具、开具结果查询、发票冲红、重试开具、发票文件重新发送五项接口能力 |
| 自营 / 撮合 | **自营**＝客户合作模式为「标准电子卡模式」，特征是平台过资金、过票（客户付款给平台、平台付款给油站，油站开票给平台、平台开票给客户）；**撮合**＝客户合作模式为「撮合模式」，客户直接付款给油站、油站开票给客户，平台收服务费。注意与「网点一级渠道=自营（平台直签站）」区分，后者是油站资源属性 |
| 蓝票 / 红票 | 蓝票为正常开具的发票；红票为对原蓝票冲红后生成的负数发票，红票与原蓝票的对应关系通过发票序列与开票记录体现（订单发票管理列表保留「关联发票」列） |
| 进项票 / 销项票 | 进项票＝油站作为销方开具给平台的发票（自营购进侧）；销项票＝平台作为销方开具给客户的发票（自营销售侧，本期仍走线下开票后上传） |
| 票池 | 进项票数量库存的既有模块：进项管理/进项库存/进项扣还明细按**货物名称＋规格**记数量，票池管理按**主体公司 × 能源类型**记额度；销项开票消耗对应品类库存 |
| 折扣行 | 发票商品明细后附带的负数金额行，金额＝**销方（油站）给购方的优惠**（自营＝油站给平台的优惠，撮合＝油站给客户的优惠，如充值返利）；判定依据＝订单实付金额中是否已拆出优惠抵扣金额，拆出才带；**平台补贴不进折扣行、不影响票面金额** |
| 消费返利 / 充值返利 | 购方（用油方）账户的两类返利余额，属于油站给购方的优惠来源之一；开票申请时其余额变动金额计入折扣行 |
| 发票进项油品映射 | 字典编码，维护「订单商品 → 发票项目名称」的映射；开票明细行的项目名称取自该字典 |
| 红冲（冲红） | 对已开具蓝票发起冲销并生成红票的动作；本需求红冲触发两类：退款审核通过（先红冲后退款）与运营手动红冲（订单操作列发起，用于换开）；**红冲仅针对乐企渠道、且只冲油站开出的那张票** |
| 开票渠道 | 订单发票的开出来源，枚举：乐企、线下。线下=既有「客户申请＋油站上传」流程 |
| 交易即开票 | 支付成功即按订单维度实时开具发票，交易与开票解耦，开票失败不影响交易完成 |
| 自动下线（熔断） | 网点公司「线上开票失败 n 笔自动下线」配置：开票失败笔数达到阈值后系统自动停用该网点公司 |
| 应开票订单 | 满足应开票范围（柴油＋易宝支付＋网点一级渠道=自营）的能源订单 |
| 审核状态 | 退款单的审核结论，取值：待审核、审核通过、审核驳回（不含资金结果；**审核人点了通过即展示「审核通过」**，退款过程看客户侧「司机支付状态」、油站侧结果看「油站扣款状态」） |

## 5.1 需求范围

- 端与用户：运营平台（PC），运营人员。
- **改造页面（现网已有）**：能源订单管理、退款申请管理（撮合订单）、自营订单管理、自营订单退款（订单中心）、网点公司管理（网点中心）。
- **落地菜单**：订单发票管理——现网开票中心已预留同名菜单（当前为空页），本次落地页面内容。
- 本期不含：天然气订单自动开票（不接乐企，按线下渠道口径处理与展示，口径不排斥后续纳入）；三方渠道站订单与非易宝支付订单（维持线下开票现状）；自营中平台开给客户的销项票线上开票（仍走线下开票后上传）；乐企能力授权的前置校验（由易宝侧线下完成开通与授权，系统不做拦截）；企业端、油站端页面；服务费订单开票；上线前已走易宝支付的历史订单（乐企不支持处理，维持原状）。

## 6.1 应用架构

运营平台各页面通过平台开票服务对接乐企开放平台：支付成功通知（易宝支付）触发乐企发票开具接口，通过开具结果查询接口轮询开具结果并回写订单开票状态与发票文件；退款审核通过（满足红冲条件时）与运营手动红冲由开票服务调用发票冲红接口；重试开具接口承担失败重试与手动开票，发票文件重新发送接口补拉发票文件。

**自营的两张票分开走**：乐企开的是油站开给平台的**进项票**（销方=油站公司、购方=平台内部主体）；平台开给客户的**销项票**沿用现网「客户对账 → 客户开票 → 开票上传」链路（线下渠道，本期不改）。撮合只有一张票：油站开给客户（销方=油站公司、购方=客户公司），由乐企自动开具。

进项票侧：乐企获取的自营订单进项票按**货物名称＋规格**归集入票池（进项管理/进项库存/进项扣还明细维护数量，票池管理按主体公司维护额度）；销项开票消耗对应品类数量库存；进项票红冲时回退库存记录（不产生负数，不追溯已开销项）。

发票与订单的关系：**一张票对应一张订单**（订单流水号精确匹配），**不落子订单/运单**；红冲按订单一次。订单、退款、发票、网点配置数据均落平台库，订单发票管理按发票维度展示全量蓝/红票。企业开通/激活/授权沿用易宝现有能力，不做接口对接。

## 6.2 产品流程

1. **支付即开票**：易宝支付成功→判定应开票范围（柴油＋易宝支付＋网点一级渠道=自营）→订单标记开票渠道=乐企→实时调用发票开具接口，开具结果查询接口轮询：成功=开票成功并取得发票文件；失败=每分钟重试 1 次×3 次（重试开具接口），仍失败停留「开票失败」并记录失败原因。开票失败不影响交易正常进行。
2. **失败熔断**：开票失败落定时，若该网点公司已开启「线上开票失败 n 笔自动下线」且当前开票失败笔数≥n，自动停用该网点公司（操作记录留存＋站内信/短信预警，并记录本次联动下线的网点清单作为恢复依据）；未配置或未达标转人工——运营在订单管理筛选「开票失败」手动开票，仍失败转技术排查。
3. **退款与红冲（按退款类型分治）**：退款审核通过时先判退款类型——**整体退款、油站退款**：若原蓝票为乐企渠道且开票成功未红冲，先调用发票冲红接口冲油站开出的原蓝票，红冲成功→执行原有退款流程；红冲失败→不执行退款，审核状态保持「审核通过」，订单开票状态置「红冲失败」、订单油站扣款状态置「退款失败」，提示原因，线下抵扣处理完成后重新发起退款申请，审核通过后再次触发红冲。**客户退款**：只退客户侧资金，不触发红冲（平台开给客户的销项票为线下处理）。红冲进行中的订单拦截审核；线下渠道发票退款不拦截，维持现状。
4. **手动红冲与重开（仅乐企渠道）**：运营对开票成功（或红冲失败重发）的乐企订单在「能源订单管理/自营订单管理」操作列发起手动红冲，调用发票冲红接口——成功→已红冲（原蓝票冲销），可再次手动开票重开蓝票，发票按蓝票→红票→新蓝票序列留痕；失败→停留「红冲失败」展示原因，可重新发起。
5. **票池库存联动**：乐企获取到自营订单的进项票后按货物名称＋规格记录到进项管理（数量入池）；销项票开票消耗对应品类数量库存，库存不足不开；进项票红冲回退库存（不产生负数，等价于消耗库存），已开销项不追溯。
6. **退款资金结果与重发**：退款审核通过→客户侧「司机支付状态」置「退款中」，油站扣款状态保持「支付成功」；资金退回成功→司机支付状态置「已退款」；油站侧退款未退成（红冲失败或资金退回失败）→油站扣款状态置「退款失败」，审核状态保持「审核通过」，处理资金侧问题后重新发起退款申请，审核通过时**红冲自动通过**（原蓝票已冲销、不重复红冲），直接走易宝资金流退款。
7. **退款中的订单不再开票**：订单处于退款中/已退款时，不展示手动开票入口，并停止开票失败自动重试。

## 7.2 功能说明（按页面）

### 7.2.1 能源订单管理

> 本节只列本次新增/修改元素；页面既有筛选项、列与操作（订单编号、订单来源、客户公司、司机信息、油站名称、支付方式、订单状态、时间范围、订单补录、批量申请开票等）保持原样。

1. 开票渠道列：展示订单开票渠道，枚举【乐企、线下】；乐企显示高亮标签、线下显示普通标签；存量无渠道标识的订单按「线下」展示。
2. 开票状态列：按订单渠道分治展示——开票渠道=乐企展示 7 值状态【未开票、开票中、开票失败、开票成功、红冲中、红冲失败、已红冲】；开票渠道=线下展示 4 值状态【未开票、开票中、已开票、已撤销】；展示最新 1 次开票（蓝票＋红票）的结果。
3. 失败原因列：开票状态=开票失败或红冲失败时展示乐企返回原因（红色文字）；其余状态展示「—」。
4. 筛选项——开票渠道：下拉单选，默认「请选择」（全部）；选项【乐企、线下】；精确匹配订单开票渠道。
5. 筛选项——乐企开票状态：下拉单选，默认「请选择」（全部）；选项【未开票、开票中、开票失败、开票成功、红冲中、红冲失败、已红冲】；精确匹配，**仅命中开票渠道=乐企的订单**。
6. 筛选项——开票状态：下拉单选，默认「请选择」（全部）；选项【未开票、开票中、已开票、已撤销】；精确匹配，**仅命中开票渠道=线下的订单**。

### 7.2.2 退款申请管理

### 7.2.8 乐企对接开票数据

本节定义调用乐企发票开具接口时的票面明细行（商品行＋折扣行）数据口径，适用于开票渠道=乐企的撮合易宝订单与自营易宝订单。折扣行属于开票申请数据，随发票票面呈现；订单管理/自营订单管理页面不新增折扣行展示，订单发票管理列表列不变（仅在金额下方展示「含折扣行 −xx.xx」）。

1. 明细行构成：商品明细行（按订单油品逐行）＋折扣行（可选，至多 1 行）；商品行必须包含项目名称、规格型号、单位、数量、单价、金额。
2. 项目名称：按订单商品在字典编码【发票进项油品映射】中查得的发票项目名称。
3. 规格型号：取该商品的「商品大类」。
4. 单位：升。
5. 数量：订单升数，四舍五入保留 5 位小数，票面与接口申请均按 5 位小数。
6. 单价：=商品行金额÷数量（反算，保留足够小数位保证 数量×单价=金额）。
7. 金额与折扣行：**折扣行金额＝销方（油站）给购方的优惠金额**（自营＝油站给平台的优惠，撮合＝油站给客户的优惠，如充值返利），判定依据＝订单实付金额中是否已拆出优惠抵扣金额：已拆出——发票带 1 行负数折扣行（挂在商品明细之后），商品行金额=原价金额（=单价×数量），价税合计=实付金额（=商品行金额−折扣金额）；未拆出——不带折扣行，商品行金额=订单实付金额。**平台补贴不进折扣行、不影响票面金额**。优惠金额的快照时点与主体（last/current 余额快照，技术字段对照：last_consume_rebate_balance / current_consume_rebate_balance / last_recharge_rebate_balance / current_recharge_rebate_balance）由技术方案定义。
8. 红票：按原蓝票票面内容负数镜像开具（项目名称/规格型号/数量/单价/折扣行同步负数，不重新计算），红票价税合计=−原蓝票价税合计，与整单退款金额（实付金额）对齐。
9. 已红冲重开蓝票：按重开申请时的优惠金额重新计算折扣行，其余口径同第 5–7 条。
10. 映射缺失兜底：订单商品在【发票进项油品映射】中无映射时开票失败、记录失败原因，走既有失败重试与手动开票路径；补配字典后可重新开票。

## 8 测试重点

1. 应开票范围判定：柴油＋易宝支付＋网点一级渠道=自营三条件同时满足才自动开票；天然气、非易宝支付、三方渠道站订单不开票且开票渠道=线下；自营中平台→客户的销项票仍走线下上传，不产生乐企发票。
2. 开票状态机与退款窗口：支付成功→开票中→开票成功/开票失败（失败重试每分钟 1 次×3 次）；退款审核通过或手动红冲→红冲中→已红冲/红冲失败；列表展示最新 1 次开票结果（蓝＋红＋再开蓝循环）；订单处于退款中/已退款时不展示手动开票、停止失败自动重试；开票中/红冲中拦截退款申请与审核。
3. 退款红冲分治与资金结果落点：整体退款/油站退款审核通过先红冲油站开出的蓝票，客户退款不红冲；审核状态在点击通过后恒为「审核通过」，红冲失败与资金退回失败都只体现在订单油站扣款状态「退款失败」；重发后审核通过时红冲自动通过、走易宝资金流退款。
4. 票池控量：自营乐企进项票按货物名称＋规格入池；销项开票消耗对应品类库存且不足不开；进项票红冲走回退、不产生负数、不追溯已开销项。
5. 票面数据：折扣行金额=油站给购方的优惠（有优惠抵扣才带 1 行、平台补贴不进）；项目名称/规格型号按字典与商品大类取值；数量=升数 5 位小数、数量×单价=金额；红票按原蓝票镜像负数且总额=−实付金额；映射缺失开票失败。
6. 熔断计数与下透：计数=该网点公司当前「开票状态=开票失败」的应开票订单数（做过红冲不算，**已退款仍计入**）≥n 触发停用，联动名下上线中网点下线并留痕预警；重新启用按记录恢复、计数清零；未开通易宝账户不可开启配置。
