# **需求背景&目标**

网货能源（油气/电）的派发节点目前支持「装车、货主结算后（一笔付）」，回收节点支持「卸货后、卸货后结算前、货主结算后N天」。业务上存在两个缺口：

1. 运单卸货完成后运费可能按磅单/实际重新计算，按装车时运费派发的额度与最终运费不匹配；需要在卸货完成时按卸货时运费执行派发，并延续分油计算扣除司机购买保费的口径（【285.4】）。
2. 货主支付运费（银企直联/虚拟钱包）的资金链路是「货主钱包/银行→平台→司机钱包/账户」：若打款后才回收运单未用额度，未用额度对应的运费已随打款流向司机、无法回收；需要在货主结算通知油气服务后先回收额度、再打款。

**目标：**

1. 能源派发节点新增「卸货」：派发节点=卸货的规则，运单卸货完成后按卸货时运费计算派发油气额度/电额度；司机购买保险的运单从计算基数中扣除保费；油气与电同口径。
2. 能源回收节点「货主结算后N天」支持配置 0 天：配置 0 天后油气不执行「支付时间+N天」的定时任务、直接进行额度回收——银企直联/虚拟钱包非一笔支付在结算通知油气回收额度后立即回收（先回收、后打款），虚拟钱包一笔支付在收到已支付通知后直接回收。

# 需求概述

1. **能源派发节点新增「卸货」**：油气规则与电规则均可配置；装车时匹配到生效规则即写入油气运单快照（分油节点、回收节点、比例等）；派发节点=卸货的运单，卸货时校验快照并按卸货时运费计算派发金额、不重新匹配规则；派发计算基数扣除司机购买保费（运费与保险信息直接从结算服务查得，不调用保险侧接口）；派发金额公式不变（基数×快照派发比例，有司机补贴再×(1−快照司机补贴比例)）。
2. **能源回收节点「货主结算后N天」支持配置 0 天**：油气规则与电规则均可配置；配置 0 天后油气不执行定时任务、直接进行额度回收——银企直联/虚拟钱包非一笔支付在结算通知油气回收额度后立即回收，虚拟钱包一笔支付在收到已支付通知后直接回收；电运单冻结额度>0 阻断支付申请。

## 需求范围

本需求涉及 4PL 运营端「能源规则配置」（筛选项与编辑页新增派发节点选项、能源回收节点「货主结算后N天」支持配置 0 天并新增回收天数输入框）、「能源运单管理」（派发节点列新增「卸货」取值的运单展示），以及网货平台的卸货派发计算、货主结算后 0 天立即回收执行逻辑（后台计算逻辑，无页面）。

明确不做：能源派发方式（按运费比例）与派发金额公式不变；每月 2 号兜底回收不变；货主支付中心的付款申请、审核、打款既有流程不改（仅在结算通知环节新增回收通知）；装货预付运费结算不通知回收（沿用现网口径）；上线前已派发/已回收的运单不做追溯。

# 需求详述

## 应用架构

**架构图**：无

**架构说明**：本需求为网货能源派发与回收链路的节点扩展：卸货派发复用既有能源派发服务，卸货时运费与保险信息（保费金额、保险购买方）直接从结算服务查得，不调用保险侧接口（【285.4】保险侧保障单查询/保费试算接口仅装车分油使用）；货主结算后 0 天回收复用能源额度服务的圈回能力，触发点为支付中心的结算通知事件，回收完成后支付中心按既有审核与打款流程执行（银企直联/虚拟钱包）。

## 产品流程

**产品流程图**（两张时序图）：

（画板 1）卸货分油/分电时序——油气与电同口径，卸货时运费与保险信息直接从结算服务查得（不调用保险侧接口）

（画板 2）货主结算后 0 天回收时序——按支付方式分线：银企直联/虚拟钱包非一笔支付先回收、后打款；虚拟钱包一笔支付 N=0 不执行定时任务、收到已支付通知后直接回收（N>0 按支付时间+N天定时回收）

**流程说明**：

1. **卸货派发**：运单卸货完成发送卸货消息 → 能源派发服务消费消息，校验运单油气快照（装车时按「车辆能源类型＋网货主体＋货主企业」匹配生效规则并记录：分油节点、回收节点、派发比例、司机补贴比例等）——快照存在且快照分油节点=卸货的，按快照完成分油计算、不重新匹配规则；无快照或快照分油节点≠卸货的不派发 → 从结算服务查询更新后的运费与保险信息（保费金额、保险购买方），按购买方判定是否扣减保费（司机购买扣减；货主购买/未投保不扣减），不调用保险侧接口 → 按基数×快照派发比例（有司机补贴再×(1−快照司机补贴比例)）计算派发金额 → 油气入账司机油气余额、电入账司机电余额 → 写派发时间（＝卸货完成时间）、派发状态＝已派发、能源变更日志。
2. **货主结算后 0 天回收（按支付方式分线）**：银企直联、或虚拟钱包非一笔支付——结算支付判断支付方式=银企直连后，通知油气服务回收额度，油气立即回收未用额度（先回收、后打款）；虚拟钱包一笔支付——结算通知油气服务已支付，油气记录支付时间，回收天数=0 时不执行「支付时间+N天」的定时任务、直接回收未用额度（N>0 时按支付时间+N天定时回收，现网既有逻辑） → 电运单冻结额度>0 阻断支付申请（提示「司机充电订单未完结，暂无法付款」）；油气司机加注中（预冻结）按回收干预矩阵冻结未用余额、订单完结后自动回收，不阻断 → 回收成功（可用额度→已圈回额度、写能源变更日志）→ 付款申请进入既有审核流程 → 审核通过打款：银企直联（货主银行→平台→司机银行账户）或虚拟钱包（货主钱包扣款→平台→司机钱包入账），打款现金金额＝运费−未用额度。
3. **支付终止与失败**：审核驳回或货主撤销支付，已回收额度不恢复、维持已回收，待下次结算时按扣减后金额直接打款；长期未支付由每月 2 号兜底回收或人工恢复闭环。审核通过后打款失败（银企转账失败/钱包扣款失败），额度维持已回收，补款成功后闭环。
4. **装货预付运费**：货主发起装货预付支付不通知回收（沿用现网口径）。
5. **分次付**：每笔结算通知油气服务时执行回收；首笔回收后运单可用额度为 0，后续笔次无额度可收、直接按既有流程打款。

### 说明

   1. 货主结算后N天：N 支持配置 0 天——0 天＝货主结算通知油气服务后立即回收未用额度（先回收、后打款）；N>0＝货主结算后 N 天回收；油气规则与电规则均可选（编辑页提示文案：「货主结算后N天：N 支持配置 0 天——0 天＝货主结算通知油气服务后立即回收未用额度（先回收、后打款）；N>0＝货主结算后 N 天回收（油气与电同口径）」）。
   2. **回收天数（编辑页字段，本次新增）**：选中「货主结算后N天」时显示；整数天，0–365，必填，默认 0；0 天＝结算通知油气服务后立即回收（见 7.2.4）。

5. **派发节点/回收节点（列表列）**：展示规则配置的派发节点、回收节点名称（派发节点含「卸货」；回收节点按「货主结算后(N天)」展示，含「货主结算后(0天)」）。

### 卸货派发计算（后台计算逻辑）

说明：

1. **触发与快照校验**：运单卸货完成触发；校验运单装车时写入的油气快照——快照存在且快照分油节点=卸货的，按快照完成分油计算（不重新匹配规则）；无快照或快照分油节点≠卸货的运单不派发。快照含分油节点、回收节点、派发比例、司机补贴比例等；规则在装车后修改/停用不影响已装车运单（以快照为准）。
2. **派发计算基数**＝卸货时运费（卸货完成时点按磅单/实际重新计算后的应付司机总运费；未重新计算的等于装车时运费）；卸货时运费与保险信息均取自结算服务。
3. **保险扣减**（油气分油与电分电同口径）：保险信息（保费金额、保险购买方）直接从结算服务查得，**不调用保险侧保障单查询接口与保费试算接口**——
   1. 保险购买方＝司机：派发计算基数＝卸货时运费−保费金额；
   2. 保险购买方＝货主 或 未投保：派发计算基数＝卸货时运费（不扣减）；
   3. 派发执行时点从结算服务查得、不落快照；派发完成后保费变化不重算、不修正已派额度。
4. **派发金额公式（不变）**：有司机补贴的运单，派发金额＝派发计算基数×派发比例×(1−司机补贴比例)；无司机补贴的运单，派发金额＝派发计算基数×派发比例。司机补贴比例按运单能源类型取柴油补贴比例、天然气补贴比例或电补贴比例；电规则派发比例受「分电上限比例配置」约束。
5. **入账与留痕**：油气入账司机油气余额、电入账司机电余额；运单记派发时间＝卸货完成时间、派发状态＝已派发；写能源变更日志（油气动作「分配」、电动作「分电」）。
6. **金额精度**：派发金额单位为元，保留两位小数。

**计算示例：**

| 场景 | 卸货时运费 | 派发比例 | 司机补贴比例 | 保险 | 派发金额 |
|-|-|-|-|-|-|
| 司机购买保险、无司机补贴 | 1000.00 | 30% | 无 | 司机购买 10.00 | （1000.00−10.00）×30%＝297.00 |
| 司机购买保险、有司机补贴 | 1000.00 | 30% | 10% | 司机购买 10.00 | （1000.00−10.00）×30%×（1−10%）＝267.30 |
| 货主购买保险 | 1000.00 | 30% | 无 | 货主购买 10.00 | 1000.00×30%＝300.00 |
| 未投保 | 1000.00 | 30% | 无 | 无 | 1000.00×30%＝300.00 |

### 货主结算后0天回收（后台计算逻辑）

说明：

1. **触发时点（按支付方式分线，N=0）**：回收节点=货主结算后N天且回收天数=0 的规则——银企直联、或虚拟钱包非一笔支付：结算支付判断支付方式为银企直连后，支付中心通知油气服务回收额度，油气立即回收本笔结算对应运单的未用额度（先回收、后打款）；虚拟钱包一笔支付：支付中心通知油气服务已支付，油气记录支付时间，不执行「支付时间+N天」的定时任务，收到通知后直接回收。
2. **回收范围**：本笔结算对应运单的未用额度（油气/电可用额度）；回收成功后运单记「已圈回额度」、司机可用额度相应减少、写能源变更日志（油气动作「圈回」、电动作「回收」）。
3. **打款与回收的先后（按支付方式）**：银企直联、或虚拟钱包非一笔支付——先回收、后打款，打款现金金额＝运费−回收的未用额度；虚拟钱包一笔支付——货主一笔付支付成功在前（资金已到司机钱包），油气在收到已支付通知后回收，N>0 按支付时间+N天定时回收（现网既有逻辑），N=0 不执行定时任务、立即回收。
4. **电运单冻结额度>0**（司机充电订单未完结）：阻断支付申请，提示文案「司机充电订单未完结，暂无法付款」；冻结额度＝0 正常回收。
5. **油气司机加注中（预冻结）**：按回收干预矩阵冻结未用余额，订单完结后自动回收，不阻断支付。
6. **支付终止**：付款申请审核驳回或货主撤销支付，已回收额度不恢复、维持已回收状态；货主下次结算时按扣减后金额直接打款；长期未支付由每月 2 号兜底回收或人工恢复闭环。
7. **打款失败**：审核通过后银企直联/虚拟钱包打款失败，已回收额度维持已回收状态，补款成功后闭环。
8. **装货预付运费**：货主发起装货预付支付不通知回收（沿用现网口径）。
9. **分次付**：每笔结算通知油气服务时执行回收；首笔回收后运单可用额度为 0，后续笔次无额度可收、直接打款。
10. **组合说明**：派发节点=货主结算后（一笔付）的规则回收天数配置为 0 天时，货主结算时运单尚无已派发额度（分油在货主支付成功后执行）、无额度可收，回收不执行、按全额打款；配置不拦截。

# 测试重点

1. **卸货派发计算**：快照分油节点=卸货的运单，卸货完成后按卸货时运费（取自结算服务）计算派发金额——保险购买方=司机扣减（（1000.00−10.00）×30%＝297.00）、货主购买与未投保不扣减（1000.00×30%＝300.00），不调用保险侧保障单查询/保费试算接口；按快照派发比例/司机补贴比例计算、不重新匹配规则（装车后规则修改/停用不影响已装车运单）；卸货运费重算（与装车时不同）时按卸货时运费。
2. **电卸货分电**：电规则派发节点=卸货时，卸货完成后按卸货时运费×分电比例派发电额度，受「分电上限比例配置」约束，保险扣减与油气同口径。
3. **货主结算后0天先回收后打款**：回收节点=货主结算后N天且回收天数=0 时——银企直联/虚拟钱包非一笔支付在结算通知油气回收额度后立即回收，回收成功后打款现金金额＝运费−未用额度；虚拟钱包一笔支付在收到已支付通知后不执行定时任务、直接回收；回收天数>0 时虚拟钱包一笔支付按支付时间+N天定时回收、行为不变。
4. **电阻断**：电运单冻结额度>0 时发起支付被阻断并提示「司机充电订单未完结，暂无法付款」；冻结额度＝0 正常回收后打款。
5. **支付终止与失败闭环**：审核驳回/货主撤销后额度维持已回收（下次支付按扣减后金额直接打款）；打款失败额度维持已回收、补款成功闭环；装货预付发起支付不触发回收。
