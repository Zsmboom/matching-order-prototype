## 1. 一句话模型

平台（万油通运营中台）把「油站」（网点）和「用油方」（客户）连起来，有两种做法：

- **自营**（平台是运营方/卖方）：客户付钱给平台，平台付钱给油站；油站开票给平台（进项），平台开票给客户（销项）。平台赚购销差价。
- **撮合**（平台是撮合方/服务方）：客户直接付钱给油站，油站开票给客户；平台只收服务费。平台赚服务费。

两条线在系统里落在**不同的菜单、不同的订单、不同的发票链路**上，不能混用一套口径。

## 3. 两条业务线对比【已确认】

**字段级区分【2026-10-22 用户确认】**：看**客户合作模式**——合作模式＝**撮合模式 → 撮合业务线**；合作模式＝**标准电子卡模式 → 自营业务线**。
注意与「网点一级渠道＝自营」（平台直签直供站，其余为三方渠道对接站）**不是同一件事**：前者是客户侧的业务线，后者是油站资源的来源属性，两者正交（自营业务线也可以用三方对接站，只是那种站开不了乐企票）。

| 维度 | **自营**（平台是卖方/运营方） | **撮合**（平台是撮合方） |
|---|---|---|
| 客户付钱给谁 | **客户 → 平台** | **客户 → 油站**（走易宝支付） |
| 平台付钱给谁 | **平台 → 油站** | 不需要，平台只收服务费 |
| 发票方向 | **油站开票给平台（进项票）＋ 平台开票给客户（销项票）** | **油站开票给客户** |
| 平台收入 | 购销差价（毛利） | 服务费（客户承担 / 油站承担，两侧可同时存在） |
| 支付通道 | 易宝线上支付（D0/D1，用油方易宝户 → 油站易宝户）**或** 平台在油站预充值、记账扣款 | **必须走易宝支付渠道** |
| 开票通道 | 乐企（250.4 起，柴油＋易宝＋直签站）｜线下 | **乐企（250.4 起）**；但**三方对接站的油站走不了乐企，只能线下开票**（用户明示） |
| 发票前置约束 | **收到油站开进来的票才会给客户开票** → 票池控量、进销项项目名称必须完全一致 | 无票池约束；能源发票＝客户申请＋油站上传（线下渠道） |
| 主菜单 | 订单中心（订单管理 / 内部公司订单 / 订单退款 …）、开票中心（客户对账·客户开票 / 上游对账·上游开票 / 进项 · 票池） | 撮合订单（能源订单管理 / 服务费订单管理 / 退款申请管理）、发票中心（能源发票管理 / 服务费发票管理） |

### 3.1 自营的两种收付方式【已确认，页面印证】

油站公司账户的**账户类型**恰好两种（财务中心 → 油站公司账户 → 账户管理）：

1. **撮合账户**（＝易宝托管账户）：客户易宝户 → 油站易宝户，平台通过易宝分账/转账完成结算（结算方式 D0/D1）；适用于「自营 + 易宝线上支付」。
2. **标准电子卡预付账户**：平台**预先在油站充值**一笔额度，司机加油后按订单**记账扣款**；对应「平台在油站预充值 + 记账扣款」方式（订单列表的**「油站扣款状态」**）。

> 因此自营订单列表同时有 **司机支付状态**（客户侧收钱）与 **油站扣款状态**（油站侧付钱）两个状态列——两侧资金不同步，必须分别看。
> 【未上线】自营业务的易宝对接（d0d1）正在做，现网自营主要靠记账/预付路径。

### 3.2 记账与层级资金【已确认（页面文案）】

- 「**总公司资金，当前分公司记账**」「**当前分公司仅记账，服务费规则读取总公司配置**」——资金在总公司，分公司做记账；服务费规则统一按总公司配置。
- 油站侧账户有「**内部签约主体**」维度：同一油站公司按内部签约主体分账户。

## 4. 价格体系【已确认，页面可见】

一笔订单在详情里同时能看到 4 组价（现网「订单详情」抽屉实测）：

| 价 | 含义 | 谁跟谁 | 页面出现位置 |
|---|---|---|---|
| **发改委价**（挂牌价） | 政府指导价 | 油站对外 | 订单详情 · 油机信息 |
| **油机价 / 枪价** | 加油机实际单价 | 油站现场 | 订单详情 · 油机信息；客户商品管理「发: 9.00 元/升」 |
| **结算价** | **平台 ↔ 油站** 的结算单价 | 上游 | 网点商品管理「结算价维护」；订单详情「结算价」 |
| **成本价** | 平台侧成本单价（毛利计算基准） | 上游 | 订单详情「成本价 / 成本金额」 |
| **企业价** | **平台 ↔ 客户** 的销售单价（司机端展示的企业价） | 下游 | 客户商品管理「企业价」；订单详情「企业价」 |
| 万联价 | 企业价基础上的优惠价＝**企业价 ×（1 − 运单补贴率）**（补贴已直接体现在万联价中） | 下游 | 现网司机端与企业价并列展示；司机端 H5（`driver-h5.html`）计价说明弹层；3.9 定稿：锁站锁价命中后隐藏 |
| 毛利 | 结算金额 − 成本金额 | 平台 | 订单详情「毛利」 |

**价格怎么来**：

- **结算价/成本价**：在「商品管理 → 网点商品管理」（油站 × 商品）维护，含「结算价维护」「允许油站调价」「计算规则」「毛利等级（S⁺/S/A…Z 共 26 档）」。
- **企业价**：在「商品管理 → 客户商品管理」按 **客户 × 网点 × 商品** 逐条**推送**，页面显示三个价与两个公式，例如
  - 价格：`发: 9.00 元/升｜结: 7.20 元/升｜油: …`
  - 企业价：`7.80 元/升`（公式定价）
  - **定价公式**：`成本价 + 0.6`（另有 `结算价 + 0` 的形态，见订单详情「定价：结算价 + 0」）
  - **返利公式**：`可开票金额 * 0`
- **推送差异是设计使然**：不同客户推送的油站数量和价格可以不同，但都不影响平台与油站的结算价（用户明示）。订单详情里的「定价 / 返利」两栏即该客户当时的推送快照。
- **客户返利 / 平台补贴 / 可开票金额**：订单详情「客户实付」区块出现（实付、企业价、可开票、客户返利、司机实付、平台补贴、补贴比例）——返利与补贴会影响可开票金额，与 250.4「折扣行」口径同源。

**司机端 H5 的计价链【已确认，2026-10-22 用户裁定 万联价＝企业价基础上计算】**

- **两个油气额度账户**：**有补贴运单账户**（按运单补贴率计价，司机端展示**万联价**，账户徽标取账户内运单最高费率，演示值 6%/8%/5% → 最高 8%）；**无补贴运单账户**（按**企业价**计价，无补贴）。同一账户内的运单共用账户口径。
- **金额顺序（写死在 H5 计价说明弹层）**：订单结算＝加注升数 × **企业价** → 司机实付＝订单结算 ×（1 − 补贴率） → 平台补贴＝订单结算 − 司机实付；**直降优惠**＝油机金额 − 订单结算；**合计优惠**＝油机金额 − 司机实付。万联价＝企业价 ×（1 − 补贴率），仅用于支付前展示，最终金额不用展示单价直接相乘。
- **组合支付**：不勾选运单＝系统按**装货时间 FIFO** 依次扣减同一网货主体下多张运单的油气额度，**补贴率取参与运单的最高值**（如 8% 覆盖 6%/5%）统一计价；勾选单张运单＝只扣该运单额度、按该运单自身费率（再点一次取消，回到组合支付）。
- **额度上限反算**：最大可结算额＝可用额度 ÷（1 − 补贴率）（按分向下取整，保证 结算×实付比例 ≤ 额度），再折算为「最大可加注油机升数」或「最大可加注油机金额」（按站点计价方式）；司机输入超限时按上限自动截断。
- **运单额度 / 企业可用额度 / 账户余额仍是三个不同概念**（沿用 §5.3），H5 运单卡展示的是**运单额度**。
- **订单状态（司机端展示）**：全部 / 待支付 / 支付成功 / 已退款；订单卡展示支付方式（同主体组合支付 · N 张运单 / 当前运单支付 / 二维码支付 · 当前运单）、实扣（待支付为「待扣」、已退款为「已退」）、枪号、万联价、结算金额、订单号与时间。
- **仍在原型之外的口径**：额度账户体系（运单额度发放/回收）、补贴率配置来源、额度扣款订单是否属 250.4「交易即开票」范围、司机端是否出票，均记入 §10.2 待确认。

### 5.3 网货平台关联【已确认】

- 订单详情有「客户类型：**网货客户司机** / 运单号：`UD…`」，即**订单 → 运单**的关联字段。
- 平台与网货平台双向同步：订单操作里有「支付同步至网货平台【支付通知】」「退款同步至网货平台【退款通知】」，文案提示「**同步后网货将为司机回收额度**」；另有「网货结算主体批量推送」「网货直签订单退款（导出结果/失败项）」。
- 运单额度、企业可用额度、账户余额是**三个不同概念**（手册已明确），不能互相替代。

### 5.4 订单状态族（一单多状态，互相不替代）

`订单状态` / `支付状态`（司机侧）/ `扣款状态`（油站侧）/ `核销状态` / `结算状态` / `上游对账状态`、`下游对账状态` / `开票状态`。

> 自营的司机支付状态与油站扣款状态**当前只确认了 5 个可见值**（支付成功 / 待支付 / 退款待审核 / 已退款 / 已取消，2026-10-22 口径）；各值的出现条件、处理人、后续流转、失败兜底尚未梳理，涉及资金状态的需求必须先补状态机。

## 7. 发票体系（自营与撮合分两条链路）【已确认页面 + 用户口径】

### 7.1 自营：进项 → 票池 → 销项（「有票才开票、进销项项目名称必须一致」）

```
油站（销方）──进项票──▶ 平台（购方）
  开票中心 → 上游开票（申请/上传/审核）→ 进项管理（导入发票：货物名称/规格大类/开票数量/已使用/剩余）
                                              ↓
                                          进项库存（按商品+规格：进项总数量 / 已开数量 / 待开数量 / 可开剩余 / 额度消耗率）
                                              ↓ 消耗
平台（销方）──销项票──▶ 客户（购方）
  开票中心 → 客户对账（对账完成 → 可开票金额）→ 客户开票（销方=平台内部公司，购方=客户）
```

- **票池**＝「柴油票池 / 天然气票池」，按**主体公司**记「剩余额度 / 总额度」；另有「进项扣还明细」（变动类型：**扣减 / 恢复**）记录销项开票对进项库存的占用与回退。
- **为什么要票池**（用户明示）：只有**收到油站的发票后才给客户开票**，所以要有池子记录「收了多少 / 开出去多少」，**避免多开发票**；且**开进来的项目名称与开出去的项目名称必须完全一致** → 落地为「进项管理」的**货物名称 + 规格大类**维度，与字典 `upper_invoice_oil`（发票进项油品映射）配合。
- 对账是开票前置：客户对账（销售侧）/ 上游对账（采购侧）对账状态＝`已撤销 / 客户确认不通过 / 平台确认不通过 / 待平台确认 / 待客户确认 / 对账完成`；对账类型＝`周期对账 / 自由对账`；对账完成才形成「可开票金额」。

### 7.2 撮合：能源发票 + 服务费发票（两条独立开票链，线下申请＋油站上传）

- 能源发票：从「能源订单管理」勾单申请 → 「发票中心 → 能源发票管理」跟踪（申请状态含 `开票中` 等）。
- 服务费发票：从「服务费订单管理」勾选 → 「服务费发票管理」跟踪；服务费承担方分**客户承担 / 油站承担**，同单可能两条，需分别核对。
- 退款处理中禁止继续开票；已开票进入红冲/作废（现网仅提示，入口随 250.4 落地）。

### 7.3 乐企（250.4，【未上线】）

- 范围＝柴油 ＋ 易宝支付 ＋ 直接与加油站结算（撮合易宝＋自营）；三方对接站、非易宝订单维持线下。
- 开票状态按渠道分治：乐企 7 值 / 线下 4 值；退款**先红冲后退款**；网点公司支持「线上开票失败 n 笔自动下线」熔断；发票中心新增「订单发票管理」。
- 现网已见「开票中心 → 订单发票管理」菜单，但**打开为空页**（功能未上线/无数据）。
